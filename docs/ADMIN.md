# Админ-панель School Kiosk

Админ-панель позволяет войти в настройки киоска по логину и паролю, управлять
расписанием, объявлениями, погодой и набором сервисов на главном экране.
Настройки хранятся в **БД приложения** (таблица `app_settings`, формат
key-value), реестр плиток — в `app_units`. Legacy-файл `settings.json`
импортируется в БД один раз при первом запуске и дальше не используется.

---

## 1. Как попасть в админку

| Среда | Способ |
|---|---|
| **Браузер по локальной сети** | На главном экране нажмите шестерёнку ⚙️ в правом верхнем углу |
| **Десктопный киоск (Tauri)** | Нажмите сочетание **Ctrl+Shift+A** (иконка в браузере не показывается) |

> Открыть киоск из браузера: адрес вида `http://<IP-киоска>:8765/` (см. панель
> «подключиться по локальной сети» на главном экране).

В обоих случаях откроется экран **«Вход в админку»**.

## 2. Вход

Логин и пароль по умолчанию:

```
Логин:   admin
Пароль:  admin
```

Значения по умолчанию задаются в конфиге бэкенда
([`backend/src/core/config.py`](../backend/src/core/config.py)) переменными
`BACKEND_DEFAULT_ADMIN_LOGIN` и `BACKEND_DEFAULT_ADMIN_PASSWORD`. Их можно
переопределить через окружение при запуске бэкенда.

> **Рекомендация.** Перед использованием в реальной школе смените пароль
> (задайте `BACKEND_DEFAULT_ADMIN_PASSWORD`), т.к. значение по умолчанию
> общеизвестно.

После успешного входа бэкенд выдаёт Bearer-токен; сессия живёт в памяти
бэкенда и сбрасывается при его перезапуске. Кнопка «Выйти» завершает сессию.

## 3. Настройки

### 3.1. Папка для изображений расписания

Поле пути на диске киоска (например `D:\KioskStatic`). Пустое поле —
используется папка по умолчанию (`<data_dir>/uploads`).

- Значение сохраняется сразу после нажатия «Сохранить».
- **Применяется при перезапуске киоска/бэкенда** — монтаж `/uploads` происходит
  на старте. После сохранения перезапустите приложение, чтобы папка вступила
  в силу.
- При смене папки **старые** изображения не переносятся автоматически: в БД
  хранятся относительные пути к файлам, поэтому новые изображения будут
  попадать в новую папку, а прежние останутся на старом месте.

> Совместимость с установщиком: если при установке был указан параметр
> `/STATICDIR=...`, этот путь подхватывается бэкендом при первом запуске как
> «seed» и становится текущим значением настройки.

### 3.2. Автозапуск при входе в систему

Переключатель «Автозапуск программы при входе в систему».

- Работает **только на Windows**: бэкенд создаёт/удаляет **ярлык `.lnk`** для
  `kiosk.exe` в папке автозагрузки пользователя:
  ```
  %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\School Kiosk.lnk
  ```
- Ярлык создаётся штатным системным инструментом (PowerShell / WScript.Shell).
  Использование папки Startup (вместо прямой записи в ключ реестра `Run`)
  не вызывает срабатывание антивируса, который блокирует изменение
  `HKCU\...\CurrentVersion\Run` из процесса Python.
- Применяется **сразу** после сохранения (перезапуск не нужен).
- На других ОС переключатель недоступен (отключён), т.к. автозагрузка не
  поддерживается.

### 3.3. Погода

- «Показывать погоду» — включает плитку и экран прогноза.
- «Сервис прогноза» — провайдер (сейчас `wttr.in`).
- «Населённый пункт» — локация для запроса.
- «Интервал обновления» — от 5 до 1440 минут. Бэкенд обновляет прогноз
  в фоне; при недоступности провайдера киоск показывает последний
  сохранённый прогноз и время обновления.

### 3.4. Объявления

- «Показывать объявления» — включает плитку и экран ленты.
- «Бегущая строка» — показывает активные объявления внизу главного экрана.
- Сами объявления создаются в разделе **«Объявления»**: заголовок, текст,
  вид (бегущая строка / лента / везде), приоритет, период показа и активность.

### 3.5. Сервисы

Раздел **«Сервисы»** управляет плитками главного экрана: видимостью и порядком.
Новые сервисы появляются в реестре автоматически после обновления приложения.

## 4. Где хранятся настройки

Настройки и контент хранятся в SQLite-БД приложения:

| Таблица | Назначение |
|---|---|
| `app_settings` | Настройки в формате key-value (`system.*`, `schedule.*`, `ui.*`, `weather.*`, `announcements.*`) |
| `app_units` | Реестр сервисов: ключ, название, видимость и порядок плиток |
| `announcements` | Объявления школы (заголовок, текст, вид, приоритет, окно показа) |
| `weather_forecasts` | Кеш последнего успешного прогноза погоды |

Основные ключи `app_settings`:

| Ключ | Тип | Описание |
|---|---|---|
| `system.static_dir` | строка \| null | Каталог изображений расписания |
| `system.local_image_dir` | строка \| null | Папка локальных расписаний |
| `system.autostart` | bool | Автозагрузка при входе в систему |
| `schedule.mode` | `single` \| `week` | Режим расписания |
| `ui.welcome_message` | строка \| null | Приветствие на главном экране |
| `weather.enabled` | bool | Показывать погоду |
| `weather.api` | `wttr.in` | Провайдер прогноза |
| `weather.location` | строка | Населённый пункт |
| `weather.refresh_interval_minutes` | int | Интервал обновления прогноза |
| `announcements.enabled` | bool | Показывать объявления |
| `announcements.ticker_enabled` | bool | Бегущая строка на главном экране |

Legacy-файл `settings.json` больше не является источником истины: при первом
запуске его значения (и seed-настройки установщика) импортируются в
`app_settings`, после чего настройки читаются только из БД. Файл можно оставить
как резервную копию.

Каталог данных:
- **dev-режим** — `backend/data/`;
- **продакшен (Tauri)** — `%LOCALAPPDATA%\com.schoolkiosk.app\`.

## 5. HTTP API (для разработчиков)

Все админские эндпоинты под префиксом `/api/v1/admin`:

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/admin/login` | Вход: `{"login", "password"}` → `{"token"}` |
| `POST` | `/api/v1/admin/logout` | Выход (требует Bearer-токен) |
| `GET` | `/api/v1/admin/settings` | Текущие настройки (требует токен) |
| `PUT` | `/api/v1/admin/settings` | Сохранить настройки (требует токен) |
| `GET` | `/api/v1/admin/units/` | Реестр сервисов |
| `PATCH` | `/api/v1/admin/units/{key}` | Видимость/название сервиса |
| `PUT` | `/api/v1/admin/units/order` | Новый порядок плиток |
| `GET`/`POST` | `/api/v1/admin/announcements/` | Список/создание объявлений |
| `PATCH`/`DELETE` | `/api/v1/admin/announcements/{id}` | Изменение/удаление объявления |
| `POST` | `/api/v1/admin/weather/refresh` | Принудительное обновление прогноза |

Публичные эндпоинты (без авторизации):

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/kiosk/config` | Приветствие, режим, сервисы, флаги погоды/объявлений |
| `GET` | `/api/v1/announcements/active` | Активные объявления (`?kind=ticker\|feed`) |
| `GET` | `/api/v1/weather/forecast` | Прогноз погоды (кеш или провайдер) |

Заголовок авторизации: `Authorization: Bearer <token>`.

Пример сохранения настройки:

```bash
curl -X POST http://127.0.0.1:8765/api/v1/admin/login \
  -H "Content-Type: application/json" \
  -d '{"login":"admin","password":"admin"}'
# → {"token":"..."}

curl -X PUT http://127.0.0.1:8765/api/v1/admin/settings \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"local_image_dir":null,"schedule_mode":"week","welcome_message":"Добро пожаловать!","autostart":false,"weather_enabled":true,"weather_api":"wttr.in","weather_location":"Москва","weather_refresh_interval_minutes":60,"announcements_enabled":true,"announcements_ticker_enabled":true}'
```

Ответ `GET /admin/settings` содержит также `autostart_supported` — поддерживает
ли платформа автозагрузку.

## 6. Проверка после изменения папки

1. Сохраните папку в админке.
2. Полностью перезапустите киоск (или бэкенд).
3. Убедитесь, что новые изображения расписания сохраняются в выбранную папку.
