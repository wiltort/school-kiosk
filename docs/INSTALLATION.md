# Установка версии приложения (dev или main) на другой компьютер

В этом документе — пошаговая инструкция, как установить нужную версию School Kiosk
на целевой компьютер: сборку из ветки **dev** или из ветки **main**.

> ⚠️ **Безопасность ключа.** Если вы уже выполнили `make update-keys`, в корне
> репозитория появились файлы `school-kiosk-update.key` (приватный!) и
> `school-kiosk-update.key.pub`. **Приватный ключ ни в коем случае нельзя
> коммитить и передавать вместе с кодом.** Перенесите его в надёжное место
> (например, в менеджер паролей) и удалите из рабочей папки, либо храните вне
> репозитория.

---

## 1. Коротко: откуда берутся установщики

- Каждая ветка собирается в установщик автоматически GitHub Actions
  (workflow [`.github/workflows/release-build.yml`](../.github/workflows/release-build.yml))
  при пуше в `dev` или `main`.
- Установщики публикуются в **GitHub Releases** с тегами:
  - `dev-v<версия>` — сборка из ветки `dev`;
  - `main-v<версия>` — сборка из ветки `main`.
- Сборка из `dev` запекает **канал dev** (автообновление идёт только из dev),
  из `main` — **канал main**. Подробнее: [`src-tauri/src/updater.rs`](../src-tauri/src/updater.rs).

---

## 2. Способ 1 (рекомендуемый): установка из GitHub Releases

Подходит, когда релизный пайплайн уже работает и в `Releases` есть готовые установщики.

### Шаг 1. Определите нужный канал
- нужна «сырая»/тестовая версия → **dev**;
- нужна стабильная для школ → **main**.

### Шаг 2. Найдите установщик
1. Откройте репозиторий на GitHub → вкладка **Releases**.
2. Выберите релиз с нужным тегом:
   - для dev — тег начинается с `dev-v...`;
   - для main — тег начинается с `main-v...`.
3. В разделе **Assets** скачайте файл:
   ```
   School-Kiosk_<версия>_x64-setup.exe
   ```
   (например `School-Kiosk_0.1.0-dev.42_x64-setup.exe`).

> Прямая ссылка на последний релиз канала:
> `https://github.com/<owner>/<repo>/releases/download/<тег>/<имя_файла>.exe`

### Шаг 3. Перенесите файл на целевой компьютер
- USB-флешка, локальная сеть, почта или любой способ передачи одного `.exe`.

### Шаг 4. Запустите установщик
Варианты запуска на целевом ПК:

| Что нужно | Команда |
|---|---|
| Обычная установка | Двойной клик по `.exe`, следовать мастеру |
| Тихая установка (без окон) | `School-Kiosk_<версия>_x64-setup.exe /S` |
| С каталогом статики | `School-Kiosk_<версия>_x64-setup.exe /S /STATICDIR="D:\KioskStatic"` |

- Установка **per-user**, права администратора не требуются.
- При необходимости установщик сам доставит WebView2 Runtime.

### Шаг 5. Проверьте установку
- После установки приложение запустится (киоск).
- Откройте админ-панель: канал должен соответствовать выбранному (`dev` или `main`).

### Дальнейшие обновления
После установки киоск автоматически проверяет **свой** канал при запуске,
скачивает новую версию и устанавливает её при следующем запуске. Ничего делать
не нужно.

## 3. Способ 2: локальная сборка и ручной перенос

Используйте, когда релизов на GitHub ещё нет или нужна конкретная сборка из
черновика ветки.

### Предпосылки (на машине разработчика)
- Rust, Node.js, Python + Poetry, Tauri CLI (`make install-tauri`);
- сгенерированные ключи подписи (см. [`README.md`](../README.md#автообновление)).

> ⚠️ **Важно.** Чтобы сборка была автообновляемой и «знала» свой канал,
> её надо собрать с переменной `KIOSK_CHANNEL` и подписать ключом. Обычный
> `make build` даст сборку **без автообновления** (updater не активирован).

### Шаг 1. Переключитесь на нужную ветку
```bash
git checkout dev && git pull    # для dev
# или
git checkout main && git pull   # для main
```

### Шаг 2. (Необязательно) задайте версию канала
```bash
make update-version v="0.1.0-dev.42"    # для dev
# make update-version v="0.1.0-main.43" # для main
```

### Шаг 3. Соберите с каналом и подписью
Windows PowerShell:
```powershell
$env:KIOSK_CHANNEL = "dev"                     # или "main"
$env:KIOSK_REPO    = "<owner>/<repo>"          # например school-kiosk/school-kiosk
$env:TAURI_SIGNING_PRIVATE_KEY = "<содержимое school-kiosk-update.key>"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "<пароль>"
$env:TAURI_CONFIG = '{"bundle":{"createUpdaterArtifacts":true}}'

make build
```

Linux/macOS (bash):
```bash
export KIOSK_CHANNEL="dev"
export KIOSK_REPO="<owner>/<repo>"
export TAURI_SIGNING_PRIVATE_KEY="<содержимое ключа>"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD="<пароль>"
export TAURI_CONFIG='{"bundle":{"createUpdaterArtifacts":true}}'
make build
```

### Шаг 4. Найдите установщик
```
src-tauri/target/release/bundle/nsis/School-Kiosk_<версия>_x64-setup.exe
```

### Шаг 5. Скопируйте и установите
Перенесите `.exe` на целевой ПК и запустите так же, как в Способе 1 (шаг 4).

> Примечание: автообновление будет находить новые версии только если для этого
> канала опубликованы релиз и фид `latest.json`. Иначе киоск просто не найдёт
> обновлений (не критично, приложение работает как обычно).

---

## 4. Разница между dev и main

| Параметр | dev | main |
|---|---|---|
| Источник ветки | `dev` | `main` |
| Тег релиза | `dev-v<версия>` | `main-v<версия>` |
| Канал автообновления | `dev` | `main` |
| Откуда приходят обновления | только из `dev` | только из `main` |
| Когда используется | тестирование, эксперименты | стабильные инсталляции |

## 5. Частые вопросы

**Нужны ли права администратора для установки?**
Нет. Установщик настроен на per-user (`installMode: currentUser`) — ставится без UAC.

**Как узнать, какая версия и канал установлены?**
В админ-панели киоска. Канал возвращает команда `get_update_channel`
(см. [`src-tauri/src/admin.rs`](../src-tauri/src/admin.rs)).

**Можно ли поставить dev и main одновременно?**
Да, это разные установки в профиле пользователя, но они перезапишут друг друга,
если ставятся под тем же пользователем. Для сосуществования ставьте под разные
учётные записи.

**Что будет, если удалить приватный ключ?**
Обновления перестанут выпускаться (старые версии продолжат работать). Поэтому
ключ и пароль важно хранить в надёжном месте.

**Не хочу, чтобы киоск обновлялся сам.**
Не собирайте сборку с `KIOSK_CHANNEL` (обычный `make build`) либо просто не
публикуйте новые релизы в этот канал.

## 6. Чек-лист после установки

- [ ] Установлен установщик нужного канала (dev или main).
- [ ] Приложение запускается, киоск работает.
- [ ] В админ-панели канал соответствует ожидаемому.
- [ ] (если нужно) задан каталог статики через `/STATICDIR`.
- [ ] Приватный ключ не лежит в репозитории/на целевом ПК.
