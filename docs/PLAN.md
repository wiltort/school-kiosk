# План разработки

## Терминология

- **Локальное расписание** — `ScheduleImage` с `is_local=true`. Файл-источник лежит
  в каталоге локальных изображений (`local_image_dir`), в БД хранится
  статическая копия + метаданные (хеш, размер, mtime).
- **Веб-расписание** — `ScheduleImage` с `is_local=false`. Файл загружается через админку.
- **Актуальное расписание** — то, которое сейчас показывается киоску. В сингл-режиме —
  единственная запись с `is_active=true`.
- **Сингл-режим** — показываем ровно одно активное расписание.
- **Недельный режим** — расписания по дням недели (TODO, отдельный этап).

## Инварианты (сингл-режим)

1. В сингл-режиме в любой момент существует **не более одного** расписания
   с `is_active=true`.
2. Активация/смена расписания — одна транзакция: деактивировать старое +
   активировать новое. Частичное состояние наружу не видно.
3. Удаление активного расписания запрещено (нужно сначала выбрать другое) —
   либо подтверждённое удаление со сбросом активности. Решение зафиксировано
   в Open questions.
4. Источник истины для «актуального расписания» — флаг `is_active` в БД.
   Легаси-настройка `current_local_schedule_image_filename` используется только
   для миграции/обратной совместимости, но не как рабочее состояние.

## Use-cases

### Настройка программы (роль: администратор)
1. Администратор открывает веб-версию приложения.
2. Нажимает иконку администрирования (красный крестик).
3. Вводит логин и пароль.
4. После успешного входа киоск остаётся на главном экране: сверху появляется строка
   меню админки («Настройки», «Расписания», «О проекте»), а иконка админа меняет
   красный крестик на зелёную галочку. Клик по галочке — выход из режима админа.
5. Нажимает пункт «Настройки».
6. Получает окно с настройками:
    - режим работы расписания (single / week)
    - папка с локальными расписаниями (`local_image_dir`)
    - короткое приветственное сообщение (до 256 символов), показывается на главном экране
    - автозагрузка

### Режим одного расписания (роль: администратор)
1. Администратор в настройках выбирает режим «одно расписание».
2. Администратор выбирает одно активное расписание (пункт «Расписания»).
3. Все остальные расписания становятся неактивными (одна транзакция, инвариант №1).
4. Публичный API при обращении к актуальному расписанию возвращает одно активное
   расписание, либо 404 → «Расписание не установлено».

### Подгрузка расписания (роль: администратор)
1. Вход в админ-режим (пункты 1–4 раздела «Настройка программы»).
2. В меню выбирает пункт «Расписания».
3. Получает окно со списком расписаний и кнопками: добавить, удалить,
   редактировать, установить по умолчанию.
4. Нажимает «Добавить», в диалоговом окне указывает название и другие поля,
   затем ОК.
5. Если данные валидны — видит новое расписание в списке.
6. Если имя совпадает с активным локальным расписанием — ошибка валидации
   (уникальность активных по имени).

### Синхронизация локальных файлов (роль: администратор)
1. Вход в админ-режим (пункты 1–4 раздела «Настройка программы»).
2. Пункт «Расписания» → кнопка «Синхронизировать локальные файлы».
3. Бэкенд сканирует `local_image_dir`, добавляет новые файлы в БД, удаляет
   записи исчезнувших файлов, обновляет метаданные изменившихся.
4. Администратор получает отчёт: добавлено N, обновлено M, удалено K.
5. Параллельно работает периодическая синхронизация (таск), чтобы обновление
   файла подхватывалось без ручного действия.

### Установка локального расписания в режиме сингл (роль: администратор)
1. Вход в админку (режим — сингл).
2. Пункт «Расписания».
3. Кнопка «Установить расписание по умолчанию» у выбранного расписания.
4. Все расписания становятся неактивными, кроме выбранного (одна транзакция).
5. Киоск сразу начинает показывать это расписание.

### Просмотр расписания в режиме сингл (роль: пользователь киоска)
1. Открыть приложение (веб или десктоп).
2. Выбрать пункт «Расписание» на рабочей зоне.
3. Получаем активное расписание.
4. Если активного расписания нет — сообщение «Расписание не установлено».

### Удаление расписания (роль: администратор)
1. Вход в админ-режим.
2. Пункт «Расписания».
3. Выбирает расписание → кнопка «Удалить».
4. Для неактивного расписания: удаляется запись БД и файл, мусор убран.
5. Для активного расписания: действие запрещено, система предлагает сначала
   установить другое расписание по умолчанию (или явное подтверждение со сбросом).
